## 一、 核心知识点与架构心智模型

在第 2 周的 Day 8 到 Day 13 中，我们分别攻克了 Query 改写（Multi-Query/HyDE）、混合检索（BM25+Dense）、Cross-Encoder 单塔精排、RAG Triad 科学评测、Milvus 标量过滤及复杂表格版面解析。

Day 14 的核心意义在于**“化零为整”**：将上述分散的技术组件组装为一套可直接投产的 **Modular Advanced RAG（模块化 RAG）系统**，建立清晰的 4 层算力漏斗拓扑与强类型契约。

### 1. Modular RAG 四层算力漏斗拓扑
```
┌─────────────────────────────────────────────────────────────┐
│ 1. 数据接入与双轨索引层 (Ingestion Pipeline)                 │
│    - Table-Aware 结构化切片                                 │
│    - Milvus HNSW 向量索引 + 强类型标量字段                   │
│    - BM25 中文分词倒排 + 平滑 IDF                           │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. 多路并发召回层 (Hybrid Retrieval Layer)                   │
│    - 第一路：Milvus 标量物理前置过滤 + 稠密向量检索 (Top-10) │
│    - 第二路：BM25 关键词精确匹配稀疏检索 (Top-10)            │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. 排名融合与算力精排层 (Fusion & Reranking Layer)          │
│    - RRF 倒数排名融合 (无量纲打分，候选池初筛截断至 Top-6)   │
│    - Cross-Encoder 单塔全交叉重排 (精算注意力，重排至 Top-K) │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. 结构化合成与溯源层 (Synthesis & Citation Layer)          │
│    - 上下文装配与事实锚定生成                               │
│    - 附带 [Doc n] 溯源引用清单与毫秒级延迟审计              │
└─────────────────────────────────────────────────────────────┘
```

### 2. 算力漏斗比（Funneling Ratio）的设计哲学
- **海量全库（$10^5 \sim 10^7$ 条）**：无法直接运行重型模型；
- **粗排召回（$20$ 条）**：Milvus 标量前置过滤 + BM25 极低开销粗筛，保障高召回率（Recall）；
- **初筛融合（$6$ 条）**：无参数、无量纲的 RRF 算法合并去重，压低候选池规模；
- **精排锁定（$2 \sim 3$ 条）**：Cross-Encoder 单塔全交叉注意力进行 $O(L^2)$ 深层语义交互，以微小延迟开销换取真值 100% 置顶。

## 三、 实战避坑实录与工业级防御（Pitfalls & Fixes）

1. **Milvus 批量向量契约防御**：
   - **踩坑**：调用 `self.milvus_client.search` 时若直接传一维向量 `data=q_v`，底层 gRPC 会误将 512 个 float 判为 512 条查询并抛出 `ParamError`。
   - **防御规范**：必须传入二维批量向量结构 `data=[q_v]`。
2. **标量字段显式投影（`output_fields`）与实体解包**：
   - **踩坑**：Milvus 检索默认只返回 `id` 和 `distance`。若不显式声明 `output_fields`，实体字段为空字典；且标量属性统一收拢在 `hit["entity"]` 下。
   - **防御规范**：显式声明 `output_fields=["chunk_id", "text", "department", "doc_type", "is_table"]`，并通过 `hit["entity"]["chunk_id"]` 提取。
3. **RRF 双路合并的 Hash Map 优雅解法**：
   - **踩坑**：传统双重 for 循环极易漏掉“仅在 Dense 中存在”的候选，且循环变量易发生跨作用域篡改。
   - **防御规范**：使用 `rrf_map: Dict[str, Tuple[float, RetrievalResult]]` 字典累加两路得分，实现 $O(N)$ 复杂度的双路并集无缝合并。
4. **集合生命周期与幂等性管理**：
   - **踩坑**：多次运行脚本时，若仅在操作系统层删除 `.db` 文件，可能受文件锁影响删除失败，导致 `create_collection` 抛出 `collection already exists`。
   - **防御规范**：在初始化时加入 `if self.milvus_client.has_collection(self.collection_name): self.milvus_client.drop_collection(self.collection_name)` 实现逻辑级强力幂等。

## 四、 面试级追问与技术沉淀（Mock Interview）

### Q1: 如果线上系统要求极高并发（QPS > 1000），无法承受每次都走 Cross-Encoder（~20ms 单次延迟），架构上你会如何分级优化？
> **Tech Lead 答题心智**：
> 1. **前置语义缓存（Semantic Cache）**：在 Ingestion 层引入 Redis/GPTCache，对高频问题通过向量相似度判定（余弦相似度 > 0.95）直接命中精排结果与生成答案，降低 80% 的模型调用；
> 2. **轻量双塔重排或 ColBERT Late-Interaction**：将 Heavy 的 Cross-Encoder 替换为 ColBERT 晚期交互机制，兼具双塔离线预计算向量与单塔 Token 级交叉的高召回特性；
> 3. **动态路由降级**：根据 Query 的置信度动态分流——若粗排 Top-1 与 Top-2 分数差异极大（显著置信），直接跳过精排；仅当 Top-3 候选分数粘连胶着时，才触发 Cross-Encoder 仲裁。

### Q2: 混合检索中，除了无参数的 RRF 算法，如果我们要采用有参数的加权线性融合（$Score = \alpha \cdot S_{dense} + (1-\alpha) \cdot S_{sparse}$），必须先解决什么数学问题？工业界通常用什么归一化方案？
> **Tech Lead 答题心智**：
> 1. **量纲不一致与尺度发散问题**：Dense Cosine 分数严格落在 $[-1, 1]$（或归一化后的 $[0, 1]$），而 BM25 得分基于非线性的饱和词频与 IDF，取值范围在 $[0, +\infty)$（常在 5~35 之间）。直接线性相加会导致 BM25 完全主导排序；
> 2. **工业级归一化方案**：
>    - **Min-Max 动态缩放**：$S'_{norm} = \frac{S - S_{min}}{S_{max} - S_{min}}$（需警惕候选极差过小导致的放大效应）；
>    - **Sigmoid / Softmax 概率化映射**：通过温度系数平滑数值分布；
>    - **这也是为什么无需归一化、抗极值扰动能力强、工业开箱即用的 RRF（倒数排名融合）成为各大向量数据库（如 Milvus / Elasticsearch / Weaviate）默认首选算法的核心原因**。
