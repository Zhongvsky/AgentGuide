    Day 02 · LangChain 核心概念

    今日主题 + 学习目标

    主题：LangChain 核心概念
    目标：理解 LangChain 六大核心模块，熟练使用 LCEL

    递进关系：Day 1 搭好的 FastAPI 是壳（收请求、返响应），今天学的 LangChain 是壳里的引擎（把 prompt → 模型 → 解析串起来）。Day 3-4 的加载/向量化是喂给引擎的燃料，Day 5-6 把三者组装成 Naive RAG。所以今天的 /chat 接口要从 mock 升级成真链路——这是本周唯一一次「同一条接口改造两次」，别跳过。

    参考骨架（自己敲，注意三段各自的输入输出类型）：

    from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain.chat_models import init_chat_model   # 或 FakeListChatModel 兜底

model = init_chat_model("gpt-4o-mini", temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是 RAG 助手，回答不超过三句话。"),
    ("human", "{question}"),
])

chain = prompt | model | StrOutputParser()
print(chain.invoke({"question": "什么是 Naive RAG？"}))

    三个必须弄懂的点：

    • 六大模块记住一句话版：Model I/O（模型进出的统一封装）、Prompts（模板化输入）、Chains/LCEL（把组件用 | 串成 Runnable）、Memory（对话历史，Day 19 细讲）、Retrieval（检索，Day 3-4 细讲）、Agents（让模型自己选工具，第 3 周）
    • LCEL 的本质：每个组件都是 Runnable，A | B 就是「A 的输出喂给 B」，所以前一段的输出类型必须对得上后一段的输入
    • invoke（一次拿全量）/ stream（逐 token 出）/ batch（批量）三个调用方式共用同一条 chain，这是第 4 周异步与批处理的伏笔

    验收标准

    /chat 返回的不再是「收到问题：xxx」这种拼接字符串，而是一句模型真实生成的回答；并且你能说清 prompt | model | parser 这三段各自的输入和输出分别是什么类型。
