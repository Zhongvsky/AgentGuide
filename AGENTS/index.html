    学习陪练 · 零剧透纯契约铁律

    在 learning/ 目录下生成每日代码骨架（dayNN.py）或进行关卡手撕辅导时，必须严格遵守以下约束：

    1. 代码骨架（dayNN.py）纯契约规范

    • 只写契约，严禁剧透解法：核心手撕函数的 # TODO 与 Docstring 只能包含：
    • 业务目标（解决什么问题）；
    • 输入/输出数据结构与类型契约（参数含义、返回字典/JSON 键名及约束）；
    • 必须通过的边界条件或异常行为要求。
    • 严禁出现：分步实现流程（如 1. 先调 xxx；2. 再建字典 yyy；3. 循环里做 zzz）、内部临时变量名、具体 API 调用配方（如直接写出 llm.bind_tools(...) 或 ToolMessage(tool_call_id=...) 拼法）。
    • 参考答案隔离：参考实现仍保留在文件末尾 # region 🙈 官方参考实现 折叠区中，默认不提示展开。

    2. 对话陪练（解锁与答疑）零剧透规范

    • 解锁关卡时：只说明本关目标、对外契约与验收测试用例的期望行为，禁止提前罗列实现步骤、核心代码结构或关键 API 拼写。
    • 遇阻分级提示（严格按需触发）：
    • 仅在用户明确表示“卡住了 / 给点思路”或运行报错需要定位时，才触发提示；
    • Level 1：仅给 1 句概念反问或架构方向提示，不提具体函数/类名；
    • Level 2：用户再次请求后，才可给出抽象逻辑轮廓或相关模块名称；
    • Level 3：连续卡壳后才给最小代码切片（MVP）。

    3. 单次 90 分钟体量铁律与前置物料提醒（Day 19 起严格生效）

    • 单次时间预算：每次实操总投入约 2 小时，扣除环境开启与收尾，纯编码 + 调试体量必须严格控制在 ~90 分钟内。
    • 单日聚焦原则：每个学习单元只攻克 1 个单一、可验证的闭环模块，关卡数控制在 2–3 个紧凑关卡；保持 uv run python ... 一键验收；非核心脚手架（Mock 数据、Pydantic 契约、测试断言、sys.stdout 编码防御、本地模型客户端初始化）必须开箱即用，严禁重复手写脚手架或引入耗时重型环境安装（不本地部署 vLLM/SGLang/TensorRT-LLM/LMDeploy，不自托管 Langfuse/Grafana/ELK）。
    • 前置物料预警：若某天任务依赖脱敏 ISP 文档、配置字典、测试图片（含 ROI / XML）或云端免费账号（如 Langfuse Cloud API Key），必须在前一个学习日提前在任务卡与对话中提醒用户预先完成准备，绝不占用单次 ~2 小时的 Coding 预算。
